# User Testing Protocol

## Session length

20–30 minutes.

## Moderator rules

- Do not explain the interface before the task.
- Ask participants to think aloud.
- Record observed behaviour separately from stated opinion.
- Do not defend the design.
- Ask “What did you expect?” after confusion.

## Customer tasks

1. Imagine your laptop stopped starting this morning.
2. Publish a repair request.
3. Explain what you expect after submission.
4. Browse matching providers.
5. Compare the offers in the customer dashboard.
6. Choose one and explain the decision.
7. Complete the validation feedback form.

## Provider tasks

1. Assume you operate an IT repair business in Riga.
2. Open the provider workspace.
3. Identify which request you would respond to first.
4. Explain what information is sufficient or missing.
5. State the price model you would accept.
6. Complete the validation feedback form.

## Metrics

- Request completion rate
- Time to complete request
- Wizard abandonment step
- Number of moderator interventions
- Provider comparison comprehension
- Offer choice rationale
- Trust objections
- Likelihood score
- Pilot commitment

## Issue severity

- Critical: blocks task completion
- High: creates wrong action or major trust loss
- Medium: causes hesitation or repeated reading
- Low: cosmetic or wording preference

## Test checklist

- Desktop 1440 px
- Laptop 1280 px
- Mobile 390 px
- Keyboard navigation
- Refresh persistence
- Empty and populated request states
- Different category filters
- GitHub Pages direct load
